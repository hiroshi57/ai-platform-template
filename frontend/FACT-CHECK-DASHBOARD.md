# ファクトチェック・ダッシュボード

`fact-check-dashboard.html` は、テキスト・画像・音声・映像の主張に対して
「情報源の確認 → 一次情報比較 → クロスチェック → 事実/意見/推測の切り分け → AI参照」
という標準的な検証手順を記録・採点・集計するための、**単一HTML・オフライン動作**のツールです。
ビルド不要で、ファイルをブラウザで開くだけで動作します(このディレクトリの
React+Viteアプリとは独立した、別配布物です)。

## 使い方

ファイルをダブルクリックしてブラウザで開くか、任意の静的ファイルサーバーで配信してください。

```bash
# ローカルで動作確認する場合(任意)
npx serve frontend
# → http://localhost:3000/fact-check-dashboard.html を開く
```

初回起動時は「本ツール固有の利用条件」への同意が必要です。同意後、以下の5タブを行き来して使います。

| タブ | 内容 |
|------|------|
| 新規/編集 | 主張の記録、一次スクリーニング(A/B/C)、①〜⑤の根拠入力、総合判定の確定 |
| チェック一覧 | 記録済みケースの検索・編集・複製・印刷・削除、JSON/CSVエクスポート・インポート、サーバー共有 |
| ダッシュボード | 判定内訳・出所区分別誤り比率・月次トレンド・将来予測(参考値)・示唆(総評) |
| 参照メディアDB | 「過去メディアとの照合(C)」で登録した画像の一覧・エクスポート/インポート・削除 |
| ガイド・参考ツール | 検証手順の考え方、外部ツールへのリンク、本ツール固有の利用条件 |

### 一次スクリーニング(A/B/C) — 「技術は絞り込み、最終判断は人」

①〜⑤の詳細検証に入る前段として、以下3つの「怪しさの当たりをつける」機能があります。
**どれもスコアが高い/低い、一致した/しなかったからといって真偽を自動判定するものではなく、
最終判断は必ず人が①〜⑥で行います。**

- **A) パターン検知** — 権威借用・緊急煽り・匿名情報源など、過去に確認された誤情報の「型」を
  正規表現で検知し「怪しさスコア」を算出します。主張本文を入力するとライブ更新されます。
  ⚠ 機械学習による継続学習ではなく、`MISINFO_PATTERNS`(コード内)の固定パターン集との
  静的な照合です。新しい手口が見つかったら、このカタログに手動で追加していく運用を想定しています。
- **B) アカウント信頼性チェック** — アカウント作成の新しさ・プロフィール画像の有無等、
  記録者が目視で確認した観察項目をチェックすることでリスクスコアを算出します。
  ⚠ SNS事業者のAPIには接続しません(オフライン方針を維持するため)。
- **C) 過去メディアとの照合** — アップロードした画像の知覚ハッシュ(dHash)を、
  このチームが「参照メディアDB」タブで育てているローカルDBと比較し、過去の別事案の
  使い回しの可能性を検出します。動画・音声ファイルの自動照合は現時点では未対応です。

## データの保存場所

既定では、入力内容は**お使いの端末のブラウザ内(localStorage)にのみ**保存されます。
「サーバー共有」機能(正規版限定)を能動的に使った場合のみ、共有された内容が
`di-tools-api.vercel.app` の汎用ワークスペースAPIに送信・保存されます。

## テストの実行方法

```bash
cd frontend
npm install
npm run test:fact-check-dashboard
```

`fact-check-dashboard.test.cjs` は jsdom 上で `fact-check-dashboard.html` をそのまま実行し、
同意ゲート・根拠ガード・下書き自動保存/復元・保存失敗時のフォールバック・CSV/JSONの
インポート/エクスポート・スキーマ正規化(旧データの欠損フィールド補完)・ライセンス登録/解除・
サーバー共有(fetchはモック)・印刷レポート・トースト通知・ダッシュボード集計などを検証します。
CI(`.github/workflows/ci.yml` の `frontend` ジョブ)でも自動実行されます。

jsdomにはレイアウトエンジンが無いため、**見た目の崩れ(CSSレイアウト・印刷プレビュー・
モバイル表示等)はこのテストでは検出できません**。実ブラウザでの目視確認は別途
Playwright等で行ってください(過去のセッションで、CSS Gridの列数不整合やモバイルでの
日本語テーブル崩れがjsdomのテストをすべて通過した状態で実ブラウザ確認により発見されています)。

同様に、jsdomは `<canvas>` の画像デコード(`getContext('2d')`・`getImageData`)に対応していないため、
「過去メディアとの照合(C)」が使う知覚ハッシュ(dHash)の正しさもjsdomでは検証できません
(呼び出しが例外を投げずnullを安全に返すことまでは検証しています)。実際に画像同士が
正しく一致/不一致判定されることは、Playwrightの実ブラウザで別途確認してください。

## アーキテクチャ上の制約(意図的な設計判断)

- **フレームワーク・ビルドツール不使用**: React/Vite等には依存せず、素のJS/DOM操作で実装しています。
  単一ファイルでの配布・オフライン動作を最優先するための判断です。
- **外部CDN・アイコンフォント不使用**: アイコンはすべてインラインSVG(`ICON_PATHS`)で自己完結しています。
- **ライセンス検証はオフラインのハッシュ照合方式**: 姉妹ツール(`standalone.html`)と同じ設計。
  クライアント側JSに秘密値を埋め込むため、ソースを読めば理論上は自己発行できる簡易な仕組みです
  (強固なDRMではなく、契約条項側での抑止を前提としています)。
- **Service Worker(I7)は意図的に導入していません**: このツールは外部CDN・APIへの依存が無い
  単一HTMLファイルとして配布され、`file://`で直接開かれることを主な想定にしています。
  Service Workerは仕様上「セキュアコンテキスト」(https、またはlocalhost等)でのみ有効で、
  `file://`プロトコルでは登録自体ができません。かつ本ツールは初回ロード後にネットワーク
  リクエストを行わない設計のため、Service Workerによる「オフラインキャッシュ」が解決する
  問題(ネットワーク不安定時に再取得できない)がそもそも発生しません。`npx serve`等の
  http(s)配信で運用するケースが今後増えるまでは、実装しても実利が無いまま複雑性だけが
  増えると判断し、意図的に見送っています(検討した上での判断であり、未着手の放置ではありません)。

## 既知の未解決事項(要ビジネス判断)

- 提供者名(`PROVIDER_NAME`)・価格ページ(`LEGAL_PRICING_URL`)は姉妹ツールの値を仮に流用しています。
  実際の販売主体・価格が確定したら差し替えてください。
- 利用規約・プライバシーポリシー(`LEGAL_TERMS_URL`/`LEGAL_PRIVACY_URL`)は姉妹ツール共通のひな形で、
  ファクトチェック業務特有のリスクを個別に想定した条項ではありません。本格的に外販する場合は
  弁護士によるレビューを受けてください(本ツール固有の注意事項はコード内の `TOOL_SPECIFIC_TERMS` と
  同意ゲートで補っていますが、これは正式な法務レビューの代替にはなりません)。

詳細な機能拡張候補は、リポジトリルートの `Task-lists.md` を参照してください。

## バージョン・変更履歴

画面フッターに表示されるバージョン番号(`APP_VERSION`)と対応する変更履歴は
`frontend/CHANGELOG.md` に記録しています。単一HTMLファイルの配布物という性質上、
自動更新の仕組みは持たないため、「実装→テスト→バージョン更新→CHANGELOG記録→
(必要なら)再配布」というサイクルを`Task-lists.md`のバックログに沿って回し続けることで
継続的な改善ループとしています。詳細は`CHANGELOG.md`の「運用ルール」を参照してください。
