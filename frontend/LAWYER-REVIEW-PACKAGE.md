# 弁護士レビュー依頼パッケージ(L4)

> **正直な位置づけ**: このファイルは「弁護士によるレビューそのもの」ではありません。
> AIエージェントは実在の弁護士による契約書レビュー(法律行為)を代行できないため、
> **実際のレビュー依頼をスムーズに行えるよう、レビュー対象・論点・関連資料を1箇所に
> 整理したもの**です。Task-lists.mdのL4は、このパッケージが揃った状態を
> 「依頼の準備完了」として扱っており、レビュー完了そのものではありません。

## 1. 対象ツール

- 名称: ファクトチェック・ダッシュボード(`frontend/fact-check-dashboard.html`)
- 提供者: 株式会社デジタルアイデンティティ(2026-08-27にユーザー本人へ確認・確定済み、L1)
- 配布形態: 単一HTMLファイル(オフライン動作、サーバー共有機能のみ正規版限定でオンライン)
- 想定利用者: 報道機関・調査チーム・企業の広報/リスク管理部門等、ファクトチェック業務を
  行う担当者

## 2. レビュー対象文書

### 2-1. 本ツール固有の利用条件(7項目、同意ゲートで表示・同意必須)

日本語原文はアプリ内(`TOOL_SPECIFIC_TERMS`、`frontend/fact-check-dashboard.html`内で検索可能)
および非公式英訳(`frontend/TERMS-EN.md`、**未レビューの参考訳**)を参照してください。
7項目の要旨:

1. 本ツールは認証機関ではない(JFC/IFCN等の公式検証・認証ではない)
2. 公表の最終判断・責任は利用者にある(名誉毀損・信用毀損リスクの所在)
3. 根拠不十分な断定表現を避けるよう注意喚起
4. データの取り扱い(原則端末内保存、サーバー共有時のみサーバー保存)
5. 第三者の著作物(引用要件)の取り扱い
6. 免責条項(提供者は責任を負わない旨)
7. 一般的な利用規約・プライバシーポリシーとの関係(下記2-2参照)

### 2-2. 一般的な利用規約・プライバシーポリシー(共通ひな形、姉妹ツールと共用)

- 利用規約: `LEGAL_TERMS_URL` = https://di-tools-legal.vercel.app/terms.html
- プライバシーポリシー: `LEGAL_PRIVACY_URL` = https://di-tools-legal.vercel.app/privacy.html
- 価格ページ: 本ツール専用のものは未確定のため「準備中」表示(L2で対応済み)

⚠ これらは姉妹ツール(コスト計算ツール等)と共通のひな形であり、**ファクトチェック業務
特有のリスクを個別に想定した条項ではありません**。本格的に外販する場合、この共通ひな形を
そのまま使い続けるか、本ツール専用の条項に置き換えるかも含めて弁護士に判断を仰ぐ必要が
あります。

## 3. 弁護士に特に確認してほしい論点

### 3-1. 名誉毀損・信用毀損リスク(最重要)
本ツールは「①〜⑤の検証手順を記録し、スコア・推奨判定を算出する」ツールですが、
その算出結果を利用者が対外的に公表した場合、公表内容についての法的責任が
**利用者側にある**という整理(免責条項)が、実際に契約上・不法行為法上有効に機能するか。

### 3-2. ライセンス方式の限界(L3の検討メモ参照)
`frontend/LICENSE-STRATEGY-OPTIONS.md`に整理した通り、オフラインのライセンスキー検証は
バイパス可能な簡易な仕組みです。契約書側で「不正なキー生成・回避行為の禁止」条項を
入れることで抑止力を担保できるか、具体的な条文案の要否。

### 3-3. データ取り扱い・プライバシー
- 既定では端末内(localStorage)保存のみだが、「サーバー共有」機能を使うと
  `di-tools-api.vercel.app`という共有APIに送信・保存される(詳細は
  `.claude/agent-memory/`内の技術メモ、または開発者に確認)。
- このサーバーは複数の姉妹ツールと共有のマルチテナントAPIであり、削除機能が
  実際には動作しない既知の制約がある(`DELETE`が成功を返すが実データが消えない)。
  この点をプライバシーポリシー上どう扱うべきか。
- 個人情報(発言者名、SNSアカウント名等)がチェック記録に含まれ得ることへの対応。

### 3-4. 著作権(引用要件)
利用者が報道記事等の全文を「本文・書き起こし」欄にコピーする運用を想定しており、
著作権法上の引用要件を利用者側の注意喚起だけで担保してよいか。

### 3-5. 「一次スクリーニング」機能の表現の適切性
パターン検知・アカウント信頼性チェック・過去メディア照合という3つの機能について、
アプリ内では「機械学習ではない」「SNS APIには接続しない」「世界規模のDBではない」等、
実態を正直に説明する文言を徹底しているが、この説明が対外的な広告・営業資料等でも
一貫して使われる前提でよいか(誇大表示防止の観点)。

## 4. 参考: 開発時に確認済みの技術的事実(法務判断の前提情報)

- サーバー共有API(`di-tools-api.vercel.app`)は2026-08-25にPOST/GET/PUTの疎通を実地確認済み。
  PUTは誤った編集キーを403で正しく拒否する。DELETEは`{"ok":true}`を返すが実際には
  削除されない(上記3-3参照)。
- ライセンスキー検証はクライアント側JS内のハッシュ照合方式(K5で難読化済みだが、
  実行時にはメモリ上に復元されるため理論上バイパス可能)。
- CSP(Content-Security-Policy)により、想定外のスクリプト実行・外部通信は技術的にも
  一定制限している(K4)。
